## 2026-09-11 - Plush RNG Engine Weight Calculation Allocations
**Learning:** In the Plush RNG engine, calculating rarity weights (`_buildWeightTable` and `pity.getMultiplier`) evaluates every rarity on every roll (~300 items). Re-deriving pity configuration objects (`resolveConfig`) and computing BigInt denominator values (`denomBig`) on every query generated over 600 allocations per roll, limiting roll throughput to ~516 rolls/sec. Memoizing static pity configs and BigInt denominators in `WeakMap` caches nearly doubled throughput to ~971 rolls/sec (~48% latency reduction per roll).
**Action:** Always cache/memoize static configuration objects and BigInt conversions when iterating over large datasets inside hot loops like RNG roll calculators.

## 2026-09-11 - Plush RNG Engine Pity Multiplier Threshold Fast-Path
**Learning:** In the Plush RNG engine, `pity.getMultiplier` is evaluated for every item (~555 rarities) during roll weight generation. Because `PityTracker.prototype.increment` increments counters for all eligible items on each roll, `count` quickly becomes non-zero for hundreds of items. A naive `if (!count)` check fails because `count > 0`, forcing `getMultiplier` to execute mastery Map lookups and `Math.round`/`Math.max` threshold arithmetic for ~500 items per roll even when `count` is far below early pity start. Precalculating `minEarlyPity = Math.max(1, Math.floor(earlyPityStart * (1 - MASTERY_CAP)))` on static pity configs allows `if (count < config.minEarlyPity) return 1.0;` to safely bypass mastery lookups and threshold math for all sub-threshold pity counts, cutting `pity.getMultiplier` latency by ~91.8% and increasing roll throughput from ~829 to ~1007 rolls/sec (+21.5%).
**Action:** Precalculate mathematical lower bounds on complex multi-variable threshold formulas in hot loops to allow simple integer comparisons to short-circuit calculation early.
